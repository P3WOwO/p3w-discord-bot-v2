# P3W Discord Bot v2.0

Чистая переписанная версия бота:
- Gemini для чата — упрощённая память: только последние сообщения канала + авто-выжимка старых
- новый системный промпт: баланс рофлов и серьёзности, короткие ответы, без занудства
- починенная генерация картинок: `gemini-2.5-flash-image` (лимит см. в логах при 429)
- статусы: случайная пара "глагол + существительное" раз в час (кушает камни, слушает пиццу...)
- команды: `ping`, `say`, `image`, `time`, `user`, `top`, `life`, `msg`, `clear`, `jtm`, `forget`
- **RPG-модуль**: охота, генерация шмота, сундуки-гача, заточка, уровни (см. ниже)
- время в войсе в Supabase
- работает на Render (health-check на `/`, `/health`, `/healthz`)

## Переменные окружения

Обязательные:
- `TOKEN`
- `CLIENT_ID`
- `GUILD_ID`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

Для Gemini:
- `GEMINI_API_KEY`
- `GEMINI_MODEL` — модель чата, по умолчанию `gemini-2.5-flash-lite`
- `GEMINI_CHAT_MODELS` — список моделей чата через запятую (fallback)
- `GEMINI_IMAGE_MODELS` — модели картинок через запятую, по умолчанию `gemini-2.5-flash-image, imagen-4.0-generate-001`

Дополнительно:
- `BASE_PROMPT` или `BASE_STYLE_PROMPT` — доп. стиль общения
- `PREFIX` — префикс команд, по умолчанию `!`
- `CONTEXT_MAX_TURNS` — сколько последних сообщений держать в контексте, по умолчанию `25`
- `CONTEXT_SUMMARY_EVERY` — раз в сколько сообщений обновлять авто-выжимку, по умолчанию `30`
- `SUPABASE_TABLE` — по умолчанию `bot_state`
- `SUPABASE_ROW_ID` — по умолчанию `main`

## База данных

Запусти `supabase_bot_state.sql` в Supabase SQL Editor (если ещё не запущен).
Схема не изменилась — старые данные совместимы.

## Локальный запуск

```bash

```

## Команды

Slash: `/ping`, `/say`, `/image`, `/time`, `/user`, `/top`, `/life`, `/msg` (админ), `/clear` (админ), `/forget` (админ), `/jtm` (админ).

Префиксные: `!ping`, `!say текст`, `!image текст`, `!help`.

Бот отвечает на упоминание (`@P3W ...`) и на реплаи на свои сообщения.
Если сообщение похоже на запрос картинки («нарисуй ...», «сгенерируй ...») — рисует.

## Как работает память

- Держим последние 25 сообщений канала (окно автоматически сдвигается).
- Старые сообщения вытесняются в архив; раз в 30 сообщений Gemini сжимает архив
  в короткую выжимку (1-3 предложения) — так бот помнит суть старых разговоров без бреда.
- `/forget` полностью очищает память канала.

## Полный сброс состояния

```sql
UPDATE bot_state

    voice_times = '{}'::jsonb,
    life_state = '{"startedAt": null}'::jsonb
WHERE row_id = 'main';
```

## RPG (Фаза 2) 🎲

Кнопочное меню: `/rpg`. Быстрый доступ: `/hunt [зона]`, `/profile`.

- **Охота**: 6 зон (Луг → Бездна) по уровням; мобы генерируются (архетип + модификатор Элитный/Проклятый/Золотой)
- **Лут**: предметы создаются процедурно — база + редкость + случайные аффиксы + уровень моба. Имена вида «Огненный меч титана»
- **17+ статов/бонусов**: HP, атака, защита, скорость, крит, вампиризм, уворот, блок, контратака, стан, отражение, пробитие, реген, +золото, +XP, удача и т.д.
- **Монеты = главная валюта**: продажа лута → сундуки-гача (4 вида, включая ключевой «Сундук бездны»), заточка шмота +1…+15 с шансом провала
- **Ключи** падают с мобов, открывают топовые сундуки
- Прогресс (уровни, инвентарь, экипировка) хранится в Supabase — таблица `rpg_state` (запусти `rpg_state.sql` в SQL Editor один раз!)

### Как настраивать баланс (без кода)

Всё контентное лежит в `src/rpg/data/*.json`:
- `mobs.json` — мобы, зоны, модификаторы (новый моб = новый блок)
- `items.json` — типы шмота и базовые статы с диапазонами
- `affixes.json` — пул аффиксов и их диапазоны
- `rarities.json` — редкости: множитель, число аффиксов, вес дропа, цвет
- `chests.json` — сундуки: цена, валюта, диапазон уровней, веса редкостей
- `stats.json` — кривая уровней, прирост статов, кулдауны, параметры заточки и боя
