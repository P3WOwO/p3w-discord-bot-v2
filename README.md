# P3W Discord Bot v5

ИИ-чат (Gemini) + базовая модерация + статистика войса. RPG-модуль удалён.

## Переменные окружения

Обязательные: `TOKEN`, `CLIENT_ID`, `GUILD_ID`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`

ИИ:
- `GEMINI_API_KEY`, `GEMINI_MODEL` (по умолч. `gemini-2.5-flash-lite`), `GEMINI_CHAT_MODELS` (fallback-список), `GEMINI_IMAGE_MODELS`
- `BASE_PROMPT` — доп. стиль общения; `PREFIX` — префикс команд (`!`)
- `CONTEXT_MAX_TURNS` (25), `CONTEXT_SUMMARY_EVERY` (30)
- `AI_USER_COOLDOWN_MS` (4000), `IMAGE_USER_COOLDOWN_MS` (20000) — антиспам на пользователя

## База данных

Схема таблицы не менялась, ничего перезапускать в Supabase не нужно.

## Команды

ИИ: `/say`, `/image`, `!say`, `!image`, упоминание бота или реплай на него. `/forget` (админ) чистит память канала.

Админ: `/clear` (с фильтром по пользователю), `/msg`, `/forget`, `/jtm`.

Статистика: `/time`, `/user`, `/top`, `/life`, статус раз в час. Музыка: `/play`, `/player`, `/pause`, `/resume`, `/skip`, `/queue`, `/nowplaying`, `/volume`, `/loop`, `/shuffle`, `/stop`, `/leave`, `/musictest` (админ). Прочее: `/ping`.


## Игровые новости в Discord

После обновления бота администратор сервера может выбрать канал публикации:

- `/news channel` — выбрать текстовый канал или канал объявлений;
- `/news status` — проверить выбранный канал и состояние;
- `/news test` — отправить тестовый embed;
- `/news disable` — приостановить публикацию.

Выбор и история отправленных уведомлений сохраняются в существующем поле `bot_state.ai_memory`; отдельная таблица или SQL-миграция не нужны. Настройка хранится отдельно для каждого сервера.

### Приём публикаций от внешнего сборщика

Добавь в переменные окружения Render секрет `GAME_NEWS_API_KEY` (длинный случайный токен). Не публикуй его в репозитории и не отправляй в Discord.

Endpoint: `POST /api/game-news`

Заголовок: `Authorization: Bearer <GAME_NEWS_API_KEY>`

Пример JSON:

```json
{
  "id": "steam-app-12345-uk",
  "title": "Название игры",
  "description": "Краткое описание акции",
  "source": "Steam",
  "url": "https://store.steampowered.com/",
  "price": "₴199",
  "old_price": "₴999",
  "discount": "-80%",
  "expires_at": "2026-11-10T20:00:00+02:00",
  "image_url": "https://example.com/game-cover.jpg",
  "source_url": "https://example.com/official-campaign"
}
```

`id` должен быть стабильным идентификатором предложения для защиты от повторной отправки. Поле `guild_id` необязательно, если в Render задан `GUILD_ID`; для нескольких серверов его можно передавать отдельно. `image_url` — прямая ссылка на широкое изображение игры/акции; `source_url` — необязательная отдельная ссылка на официальный источник. Endpoint принимает JSON до 32 KB и публикует сначала отдельный широкий блок с изображением, затем информационную карточку с ценой, скидкой, сроком и кнопками-ссылками в канал, выбранный через `/news channel`. Буквальные последовательности `\\n` в описании автоматически преобразуются в переносы строк.

Этот endpoint — приёмник готовых предложений. Сам ежедневный сбор скидок/раздач и их проверка подключаются отдельным сборщиком.


### Автоматическая доставка из GitHub

Файл `.github/workflows/forward-game-news.yml` отправляет JSON-файлы из `game-news/queue/*.json` в P3W после push в `main`.

Для работы добавь два repository Actions secrets:

- `GAME_NEWS_API_KEY` — тот же секрет, что задан в Environment Render у сервиса P3W.
- `GAME_NEWS_CHANNEL_ID` — резервный ID канала для новостей, если сохранённая настройка недоступна после перезапуска. Команда `/news channel` сохраняет выбранный канал и переопределяет резервный.
- `P3W_API_URL` — публичный HTTPS URL сервиса Render без завершающего слеша.

Публикации создаются непосредственно в `main` в `game-news/queue/`; Pull Request для каждой новости не нужен. Внешний автор должен иметь доступ к GitHub connector и право записи в репозиторий.

## Музыка

P3W может воспроизводить ссылки YouTube, SoundCloud, Spotify и Яндекс Музыки, а также искать треки по названию. Для Spotify берутся метаданные трека, а само аудио подбирается из доступных источников (в первую очередь YouTube). Воспроизведение и очередь отдельные для каждого сервера.

Все команды работают в голосовом канале:
- `/play query [next]` — ссылка или название трека; бот подключится сам. `next` ставит трек следующим.
- Под текущим треком бот держит **панель с кнопками**: ⏮ ⏯ ⏭ ⏹ 🔁 (повтор: выкл / очередь / трек), 🔀 перемешать, 🔉 🔊 громкость ±10, 📜 очередь (с переходом к любому треку и страницами), 👋 выйти. Кнопки работают только для тех, кто в одном голосовом канале с ботом. `/player` присылает панель заново.
- `/pause`, `/resume`, `/skip`, `/stop`, `/loop`, `/shuffle`, `/volume percent`, `/queue`, `/nowplaying`, `/leave` — то же самое командами.
- `/musictest` (только админ) — вручную проверяет системный FFmpeg, FFmpeg→Opus, нативный Opus encode/decode, поиск и первые байты YouTube, поиск SoundCloud и открытие реального аудиосегмента. Для разовой автономной проверки после деплоя включается секрет `MUSIC_DIAG_AUTOJOIN=true`: бот подключится только к единственному занятому voice-каналу основного сервера, попробует передать 5 секунд SoundCloud-аудио через FFmpeg и Opus, выведет PASS/FAIL в Render logs и отключится. При нуле или нескольких занятых каналах автоподключение пропускается. После теста секрет нужно выключить. При сбое логируются stderr, exit code и signal FFmpeg.
- Бот сам выходит из канала, если в нём никого не осталось 2 минуты, и через 3 минуты после конца очереди.

Бот должен иметь права **Connect** и **Speak** в голосовом канале. Для воспроизведения используется системный `ffmpeg` из Native Node runtime Render (Debian 12). `ffmpeg-static` удалён: в Linux-сборке `ffmpeg-static@5.3.0` есть известная проблема с фактической версией скачиваемого бинарника. Дополнительно `/musictest` проверяет системный FFmpeg, кодирование FFmpeg в Opus и нативный Opus encode/decode.

### Источники музыки

- **YouTube:** звук берётся через `ytdl.download()` из `@distube/ytdl-core 5.x` и отдаётся ffmpeg через локальный мост (127.0.0.1), а не голой ссылкой googlevideo. Если YouTube не отдаёт звук, трек автоматически ищется на SoundCloud (совпадение по длительности), а в панели видно, откуда играет. Для ссылок на ролики, которые не открываются, название берётся через oEmbed. Если YouTube просит подтвердить, что вы не бот, добавь необязательный секрет `YT_COOKIE` в Render. Cookie не добавляй в GitHub и не отправляй в Discord.
- **SoundCloud:** работает через официальный экстрактор DisTube; поддерживаются треки и подборки.
- **Spotify:** сам Spotify не отдаёт боту аудиопоток. Плагин получает название и исполнителя и ищет аудио в других подключённых источниках.
- **Яндекс Музыка:** поддерживаются публичные ссылки на треки, альбомы и плейлисты. Плагин включается только после настройки двух секретов Render: `YANDEX_MUSIC_OAUTH_TOKEN` и `YANDEX_MUSIC_UID`. Токен и UID должны принадлежать одному аккаунту. Вне российского VDS для API может потребоваться Premium-подписка Яндекс Музыки.

Установленные env-переменные для дополнительных источников не обязательны для запуска всего бота. Без `YANDEX_MUSIC_OAUTH_TOKEN` и `YANDEX_MUSIC_UID` остальные источники продолжат работать, а ссылки Яндекс Музыки покажут подсказку по настройке.

Node.js: `24.22.1` (минимум для актуального YouTube-экстрактора — `22.22.2` или `24.15.0`).
